# Grid Demand Dashboard

Real-time US electricity demand across 15 balancing authorities (~95% CONUS). Microservices pipeline on Docker Compose and Kubernetes with Redis Streams, Postgres, and 17 HPAs.

Data source: [EIA v2 API](https://www.eia.gov/opendata/) (free, government-published, no row caps).  
Course: CSC 258, Distributed Systems, Sacramento State.

## How it works

15 fetchers each poll EIA every 20 min for their assigned BA and publish to a Redis stream. The aggregator reads via a consumer group, upserts into Postgres (one row per BA per hour, keyed on `(region, hour_bucket)`), and mirrors the last 48 buckets in memory for fast reads. On restart it hydrates from Postgres and replays any unacknowledged stream messages. The React frontend polls `/api/demand` and `/api/demand/history` every 10 min.

**Redis Streams over pub/sub**: messages persist on the log while the consumer is down, enabling replay.  
**Postgres**: durable store of record. Redis is the message bus only.

**Coverage:** CAISO, ERCOT, PJM, MISO, NYISO, ISONE, SPP, BPAT, TVA, SOCO, FPL, DUK, SRP, PSCO, PACE.

## Architecture (Kubernetes)

| Component | Replicas | Notes |
|---|---|---|
| `redis` | 1 | Stream bus. No PVC. |
| `postgres` | 1 | Durable store. 1 Gi PVC. |
| `fetcher-*` ×15 | 1–3 (HPA, 70% CPU) | Same image, `REGION` env differentiates. |
| `aggregator` | 1–5 (HPA, 50% CPU) | Read-path bottleneck. Hydrates from Postgres on start. |
| `dashboard` | 1–3 (HPA, 60% CPU) | nginx + React build, proxies `/api/` to aggregator. |

**44 K8s objects** (19 Deployments, 17 HPAs, 4 Services, 2 Secrets, 1 PVC, 1 Namespace) generated from a single Helm chart by ranging over `fetcher.regions[]` in `values.yaml`.

## Running

### Docker Compose

```bash
docker compose up --build
```

Dashboard: http://localhost:8080 · API: http://localhost:3000/api/demand · First readings ~60 s.

### Kubernetes (GKE)

```bash
# 1. Cluster (3-5 min)
gcloud container clusters create grid-demand \
  --zone us-central1-a --num-nodes 2 --machine-type e2-small \
  --release-channel regular --enable-ip-alias
gcloud container clusters get-credentials grid-demand --zone us-central1-a

# 2. Images
docker buildx build --platform linux/amd64 --push --tag ashuftw/grid-demand-fetcher:latest services/fetcher
docker buildx build --platform linux/amd64 --push --tag ashuftw/grid-demand-aggregator:latest services/aggregator
docker buildx build --platform linux/amd64 --push --tag ashuftw/grid-demand-dashboard:latest services/dashboard

# 3. Deploy
helm upgrade --install grid-demand charts/grid-demand --set eiaApiKey=$EIA_API_KEY

# 4. Dashboard IP (~30-60 s)
kubectl -n grid-demand get svc dashboard -w
```

Teardown: `helm uninstall grid-demand && gcloud container clusters delete grid-demand --zone us-central1-a`

### Kubernetes (Minikube)

```bash
minikube start --driver=docker --cpus=4 --memory=4096
minikube addons enable metrics-server
eval $(minikube docker-env)
docker build -t ashuftw/grid-demand-fetcher:latest services/fetcher
docker build -t ashuftw/grid-demand-aggregator:latest services/aggregator
docker build -t ashuftw/grid-demand-dashboard:latest services/dashboard
helm upgrade --install grid-demand charts/grid-demand \
  --set eiaApiKey=$EIA_API_KEY --set image.pullPolicy=Never \
  --namespace grid-demand --create-namespace
```

### Elasticity (HPA scale-out)


Hammers `/api/demand` for 60 s while sampling HPA state every 5 s. Writes `latency.csv` and `samples.csv` to `experiments/`.

| Metric | Value |
|---|---|
| Requests | 12,883 |
| Throughput | 215 req/s |
| p50 / p95 / p99 | 8 ms / 15 ms / 91 ms |
| Max | 312 ms |
| Errors | 0 |
| Scale-up | ~38 s to 2 replicas |
| Peak CPU | 106% |

### Chaos / recovery (pod kill)

```bash
NAMESPACE=grid-demand ./scripts/chaos-recovery.sh
```

Deletes the aggregator pod, polls `/api/health` every 200 ms, diffs before/after demand payload.

**Results (4 trials):** median **23 ms** recovery · 15/15 BAs intact · 0 messages lost.

## Challenges

**Iteration 1 (Docker Compose)**

- **EIA respondent code mapping**: the EIA API uses its own codes (`CISO`, `ERCO`, `SWPP`, `NYIS`, `ISNE`) that don't match the common ISO names. Required building an explicit lookup table and verifying each mapping against live API responses.
- **Consumer group XACK semantics**: the aggregator must `XACK` only after the Postgres upsert succeeds, not when it reads the message. Getting this order right was non-trivial since a crash between read and write would silently drop data.
- **Poll cadence vs. EIA publish cadence**: EIA publishes hourly, so polling every minute wasted 59 of 60 calls and caused stair-step artifacts in the trend chart. Settled on 10-minute polling with hour-bucket deduplication in the aggregator.
- **Unified schema across 15 BAs**: an early prototype used gridstatus.io, which had per-ISO column quirks that required custom parsing per region. Migrating to EIA gave one consistent schema across all 15 BAs at the cost of dropping to hourly granularity.
- **Postgres GENERATED column rejected**: we wanted `to_char(timestamptz)` as a generated primary key column for hour-bucketing, but Postgres requires generated expressions to be `IMMUTABLE` and `to_char` on `timestamptz` is only `STABLE`. Moved the bucket computation to application code.
- **Docker Compose dependency ordering**: `depends_on` with `condition: service_healthy` was necessary to stop the aggregator and fetchers from connecting before Redis and Postgres were actually ready, not just started.

**Iteration 2 (Kubernetes)**

- **Hand-written manifests didn't scale**: 23 nearly-identical YAML files for 15 fetchers meant every config change had to be applied 15 times. Refactored to a single Helm chart that ranges over `fetcher.regions[]`, producing 44 K8s objects with roughly 600 fewer lines.
- **Helm chart env var typo**: the fetcher Deployment template initially mounted the EIA key as `GRIDSTATUS_API_KEY` instead of `EIA_API_KEY`, which caused all 15 fetcher pods to crash-loop on the first deploy. Caught by reading pod logs.
- **metrics-server required for HPA**: GKE includes it by default but Minikube does not. Skipping `minikube addons enable metrics-server` left HPAs reporting `<unknown>` CPU utilization and never triggering a scale event.
- **15-colour differentiation**: assigning 15 distinct hues that are readable on both the map and the chart proved difficult. Added a magnitude treemap where area is proportional to MW, so scale is visible from size before colour.
